Reflection を実行し、**失敗を言語化して外部メモリに記録する**。ループが学習するための唯一の手段。

## 対象

- 引数 $ARGUMENTS に Issue 番号を指定する。未指定の場合は `loop-state.sh show` の `issue` を使う。

## いつ実行するか（いずれも必須）

- インナーループが完了した直後（差し戻しが1回でも発生した場合は特に必須）
- **ハードストップが発動した直後**（解決できなかった事実こそ最も価値がある）
- レビューで同じ指摘を2回以上受けたとき

「特に問題なく終わったから記録不要」という判断は原則しない。
差し戻しゼロで終わった場合のみ、記録をスキップしてよい（その旨を報告する）。

---

## 手順

### Phase 1: 事実の収集

推測を書かないために、まず事実を集める。

```bash
bash .claude/scripts/loop-state.sh show     # retry 回数・ゲート結果・history
git log --oneline main..HEAD                 # 何をどう直したか
git diff main...HEAD --stat                  # 変更範囲
```

収集する事実:
- どのゲートで、何回、何が落ちたか
- 各リトライで**何を変えたか**（history の note）
- 最終的に何が効いたか（ハードストップの場合は「何も効かなかった」も事実）

### Phase 2: 教訓の抽出

集めた事実から、**次のセッションが読んで行動を変えられる**教訓を抽出する。

抽出の基準:

| 記録する | 記録しない |
| --- | --- |
| このコードベース固有の落とし穴 | 一般論（「テストは大事」） |
| ライブラリ・フレームワークの想定外の挙動 | 単純なタイプミス |
| 規約の解釈がぶれた箇所 | 一度きりの環境問題 |
| 受け入れ条件の設計漏れパターン | 「気をつける」で終わる反省 |
| 解決できなかった問題と、試して無駄だったアプローチ | |

**「次回ルール」が書けない事象は教訓ではない。** 記録しない。

### Phase 3: 重複チェック

```bash
grep -n "次回ルール" .claude/memory/lessons.md
```

同じ教訓が既にある場合は**新規追加しない**。既存項目に再発を追記する:

```md
- **再発**: 2026-09-01 #43（同じ原因で2回目。ルールが守られていない → CLAUDE.md への昇格を検討）
```

**同じ教訓が3回再発したら**、それは教訓ではなくルール違反。
`.claude/rules/` 側への恒久ルール化をマスターに提案する。

### Phase 4: 記録

`.claude/memory/lessons.md` の「## 教訓」直下に、**新しいものを上に**追記する。

```md
### YYYY-MM-DD / #<Issue番号> <一行タイトル>
- **事象**: <観測できた事実のみ。解釈を混ぜない>
- **原因**: <確認できた原因。確認できていない場合は「未確定」と明記>
- **対処**: <どう直したか。ファイル名まで書く>
- **次回ルール**: <次のセッションが読んで行動を変えられる一行>
```

ハードストップの場合は以下も併記する:

```md
- **未解決**: <何が解決できなかったか>
- **試して無駄だったこと**: <次の誰かが同じ道を辿らないように>
```

### Phase 5: 報告

```
## Reflection 記録: Issue #<番号>

### ループ統計
- リトライ: X回 / ハードストップ: 有 / 無
- 最も詰まったゲート: <ゲート名>（X回失敗）

### 記録した教訓
1. **<一行タイトル>**
   - 次回ルール: <一行>

### 既存教訓への追記（再発）
- <項目名>（通算X回目）

### ルール昇格の提案
- <3回以上再発した教訓があれば、.claude/rules/ のどのファイルに何を追記すべきか>
- 無ければ「なし」

### 記録をスキップした事象
- <記録しなかった事象と理由>
```

---

## 注意

- **取り繕わない**: 「学習が効いた」と書きたいがために事実を歪めない。効かなかったなら効かなかったと書く。
- **憶測を書かない**: 原因が特定できていない場合は「未確定」と明記する。断定した誤情報は、次のセッションを間違った方向に誘導する。
- **肥大化させない**: `lessons.md` が30項目を超えたらカテゴリ整理と陳腐化項目の削除をマスターに提案する。
- **コミットする**: `lessons.md` はチームと未来のセッションの共有資産。ローカルに置き去りにしない。
