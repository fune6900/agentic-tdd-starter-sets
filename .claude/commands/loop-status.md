現在のループ状態を確認する。ハードストップまでの余力と、詰まっている箇所を把握するための点検コマンド。

## 手順

### 1. ループ状態の取得

```bash
bash .claude/scripts/loop-state.sh show
```

状態ファイルが無い場合は「ループ外の作業中」と報告して終了する。

### 2. ハードストップ判定

```bash
bash .claude/scripts/loop-state.sh check
```

exit 1 の場合はハードストップ到達。**その事実を最優先で報告する。**

### 3. 作業状況の確認

```bash
git branch --show-current
git status --short
bash .claude/scripts/worktree.sh list
```

### 4. 外部記憶の状態確認

```bash
bash .claude/scripts/loop-journal.sh status
```

確認する点:

- **Vault が接続されているか**。未接続なら `flush` ができず、エピックを閉じられない
- **未フラッシュの内部ジャーナルが残っていないか**。完了済みエピックのジャーナルが残っているのは
  `flush` の飛ばし忘れ。放置するとリポジトリに経緯が溜まり続け、Vault は空のままになる
- **進行中エピックが想定と一致しているか**

### 5. 教訓の残量確認

```bash
grep -c "^### " .claude/memory/lessons.md
```

30項目を超えている場合は整理をマスターに提案する。

## 報告フォーマット

```
## ループ状態

### 対象: Issue #<番号> / ブランチ <branch>
### 状態: running / halted / completed / ループ外

### 余力
| 項目 | 現在 | 上限 | 残り |
|------|------|------|------|
| リトライ | 1 | 3 | 2回 |
| 経過時間 | 18分 | 60分 | 42分 |
| 同一ゲート連続失敗 | G2: 1 | 2 | 1回 |

### ゲート状況
| ゲート | 結果 | 最終更新 | 理由 |
|--------|------|---------|------|
| G1 機械 | ✅ | 12:04 | |
| G2 実証 | ❌ | 12:18 | 受け入れ条件 #2 が未達 |
| G3〜G5 | 未実行 | | |

### 経緯（history）
1. <時刻> gate G1 pass
2. <時刻> gate G2 fail — <理由>
3. <時刻> retry 1 — <何を変えたか>

### 判定
続行可能 / **ハードストップ到達（人間の指示待ち）**

### 外部記憶
| 項目 | 状態 |
|------|------|
| Vault 接続 | 接続済み `<path>` / **未接続** |
| 進行中エピック | <epic-slug> |
| 未フラッシュのジャーナル | <epic-slug>（N エントリ）/ なし |
| Vault の最終記録 | <直近のエピック見出し> |

### 次にやるべきこと
<具体的な次の一手。ハードストップ時は「マスターへの報告と選択肢の提示」>
```

## 注意

- **同じ修正を繰り返していないか history で確認する。** 繰り返しているなら、残りリトライがあっても人間に相談する
- ハードストップ到達時は、状態を勝手に `clear` して再開しない。マスターの許可が必要
- 教訓ファイルは読むだけ。このコマンドで書き換えない（書き込みは `/loop-retro`）
- ジャーナルもこのコマンドで書き換えない。`flush` は `/epic-flow` の Phase 5 の仕事
- 未フラッシュのジャーナルを見つけても**手で削除しない**。中身は Vault にまだ無い
