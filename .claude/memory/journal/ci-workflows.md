## 2026-09-08T12:14Z / #5 / impl — テンプレート CI とテストスイート

- **やったこと**: `tests/`（ランナー + 4スイート・計85件）と `.github/workflows/template-ci.yml` を追加
- **なぜこの構成にしたか**:
  - 外部フレームワークに依存しない純 bash。テンプレートに npm を持ち込むと、導入先の
    スタック選択を縛るうえ、テンプレート自体のインストールが必要になる
  - 検証は全て `mktemp -d` の隔離環境。実リポジトリと実 Vault を汚さないことを最優先にした
  - `shell-lint` を独立スイートにしたのは、`grep -P` が macOS の BSD grep で動かないため。
    CI だけで回るチェックはローカルで検証できず、開発者が壊したことに気づけない。perl 版にして両方で回す
- **捨てた選択肢**:
  - bats（bash テストフレームワーク）→ 導入先に依存を増やしたくない
  - CI 側にだけ検査ロジックを書く → ローカルで再現できないチェックは維持されなくなる
- **テストが見つけたバグ**: `loop-state.sh` の `cmd_check` に多バイト隣接の変数展開が残っており、
  同一ゲート連続失敗での停止時に `halt_reason` が null になっていた（PR #4 では
  `loop-journal.sh` しか直していなかった）。`worktree.sh` と `loop-guard.sh` にも同じ書き方が残っていた
- **shellcheck**: warning 以上を5件検出し全て修正（SC2155 x2, SC2034 x3）。現在は警告ゼロ

## 2026-09-08T12:20Z / #6 / impl — 導入先 CI の自動生成

- **やったこと**: `.claude/scripts/bootstrap-project.sh` と SessionStart フック、テスト33件を追加
- **なぜこの設計にしたか**:
  - 初回起動の検知は SessionStart フック。stdout がそのままコンテキストに入る仕様なので、
    生成したときだけ喋らせ、何もしないときは黙らせる（--quiet）
  - 「生成しない条件」を先に固めた。人のリポジトリに勝手にファイルを撒く挙動は許されない。
    既存 ci.yml があれば触らない / スタック未検出なら何もしない / LOOP_BOOTSTRAP=0 で全停止
  - テンプレート自身での誤発火は「package.json が無ければ何もしない」で自然に防げる。
    テンプレート判定用のマーカーファイルを置く案は、導入先にコピーされて意味を失うので捨てた
  - パッケージマネージャは宣言（packageManager フィールド）ではなくロックファイルで判定する。
    宣言はズレるがロックファイルは事実だから
- **テストが設計の穴を突いた**: 当初 lint/typecheck/test/build のいずれも無いと即終了する実装で、
  e2e だけのプロジェクトで CI が1本も生成されなかった。quality ジョブを条件付きにして修正
- **もう1件**: pnpm/yarn で `npx playwright install` を使うとローカル解決に失敗しうるため、
  マネージャごとの exec（pnpm exec / bunx）に切り替えた
- **次**: G1〜G4

  - 複数ロックファイル検出時に警告

  YAML 検査が PyYAML 不在で黙って縮退しないよう CI で明示インストール + node-version の意味検証を追加
- **自分でも同じ罠を踏んだ**: 修正中に `${NODE_VERSION}（${NODE_SOURCE}）` を裸で書き、
  多バイト隣接の unbound variable を再発させた。**自分で作った shell-lint が即座に検出した。**

## 2026-09-09T11:35Z / #6 / gates — 入力経路の全棚卸し（3巡目）

- **やったこと**: 個別の指摘対応をやめ、**外部入力が生成物・破壊的操作・記録に流れ込む経路を全て棚卸し**した
- **なぜ方針を変えたか**: 2巡連続で「直した箇所の隣」に穴が出た。指摘された箇所だけ直す限り、
  同じ障害クラスの別経路が残り続ける。経路の全数調査でしか止まらないと判断した
- **見つかった穴（5件）**:
  1. **[最重要] ハードストップが黙って無効化される**: 上限の環境変数が非数値だと jq の --argjson が落ち、
     0バイトの loop-state.json が残る。以後 check は全比較が失敗して **exit 0（続行可）** を返す。
     loop-guard も status を読めず素通し。`LOOP_MAX_RETRY=abc` のタイプミス1つで無限リトライになる
  2. **記録への注入**: Issue 識別子と題名に改行を通せる。ジャーナルに偽の `## ` 見出しを注入でき、
     次のセッションが読む記憶と、flush 先の Vault の両方を汚染できる
  3. **frontmatter の破壊**: 題名の引用符でジャーナルの YAML frontmatter が壊れる
  4. **worktree のパス脱出**: ブランチ名 `..` が `$WORKTREE_ROOT/..` を指す
  5. **[根が深い] grep ベース検証の複数行すり抜け**: `printf '%s' "$x" | grep -Eq '^...$'` は
     **grep が行単位で判定するため、1行目がマッチすれば合格になる**。
     `valid_slug`（traversal を防いでいる本体）・`require_branch`・`engines.node` の全てが該当。
     slug は多層防御の2層目で辛うじて止まっていたが、worktree と bootstrap には2層目が無かった
- **なぜ 5 を作ったか**: 「正規表現で allowlist する」という発想のまま、`grep` の入力単位を確認しなかった。
  同じ書き方を3箇所にコピーしたので、穴も3箇所に増えた
- **対処**:
  - 検証を全て `case`（文字列全体を1パターンと突き合わせる）へ置換。grep は使わない
  - loop-state を fail-closed に。状態が読めなければ**止まる側**へ倒す。書き込みも JSON 検証を通す
  - Issue 識別子を検証、題名は改行・制御文字を落として1行化
  - worktree のブランチ名を検証（`..` / 先頭ハイフン / スラッシュ位置 / 文字種）
  - `.nvmrc` は文字種に加えて形式（数字始まり / lts/* / node / stable）も見る
- **テスト**: 218件（+51）。worktree.test.sh を新規作成（PR #7 のレビュー指摘で未カバーだった）
- **ついでに見つけた**: `tests/run.sh` が REPO_ROOT を環境変数から受け取らず git から上書きしていた。
  **隔離コピーへの変異テストが実物を走らせていた**。個別テストは環境変数を尊重するのに矛盾していた
- **再検証**: 今回の防御を全て巻き戻す変異で、4スイート計19件が FAIL することを確認

## 2026-09-09T12:40Z / #10 / gates — G5 セキュリティゲート差し戻し対応

- **結果**: G5 で FAIL。重要度「高」2件・「中」4件・「低」5件。前回3巡で潰した5件は本物と確認された
- **高1: SessionStart 経由のプロンプトインジェクション**
  `engines.node` を**採用の可否だけ検証**し、警告出力には生で流していた。
  `note()` は `--quiet` でも必ず出力し、SessionStart の stdout はコンテキストに入る。
  他人のリポジトリを clone して開いた瞬間、**ユーザー操作ゼロで攻撃者の指示文がコンテキストに入る**
  → 値を一切出さず**長さだけ**報告する形に変更。改行を潰して切り詰めても、
  断片は攻撃者の制御下にある文字列のままだと判断した
- **高2: `assert_in_journal_dir` が実質恒真だった**
  slug が `/` を通さない以上 dirname は必ず `$JOURNAL_DIR` になる。
  **「多層防御」と自称しながら何も守っていなかった。** ファイル自体のリンク性を見ていない。
  `journal/*.md` は Git 管理下なので、悪意ある PR にリンクを1本混ぜるだけで
  CLAUDE.md が定める「最初の行動」= `context` が秘密ファイルの読み出し装置に化ける
  → ファイルとディレクトリ両方のリンク性を検査。`cmd_context`（ノーガードだった）と
  `cmd_outer` の退避経路にも検査を追加
- **中: `write_state` の戻り値を全て捨てていた**
  正しく拒否して 1 を返す実装にしておきながら、`cmd_init` 以外の4箇所が受け取っていない。
  **3巡目で潰した「ハードストップの静かな死」と寸分違わぬ形**。書き込み不能な環境で
  retry が永久に加算されず、上限が効かないまま回り続ける
- **中: リモート URL の認証情報が Vault へ平文で残る**
  Vault はリポジトリ外＝.gitignore も権限設定も届かず、多くの場合クラウド同期される。
  追記専用なので後から消しても同期先の履歴に残る
- **中: bootstrap がリンク経由でリポジトリ外へ書く / actionlint を完全性検証なしで root 実行**
- **なぜ高1・高2を作ったか**:
  - 高1: **検証を「採用の可否」にしか使っていなかった**。入力の行き先を数え漏らした。
    生成物には入れないのに、警告出力という別の出口があることを勘定していない
  - 高2: 「ディレクトリが一致すれば安全」という前提を、**検査が恒真になる条件を確かめずに**書いた。
    自分でコメントに「多層防御」と書いたことで、検証した気になっていた
- **対処**: 高2件・中4件・低5件を全て修正。テスト 254件（+25）
- **再検証**: G5 の修正を巻き戻す変異で、bootstrap 5件・loop-journal 6件が FAIL することを確認
