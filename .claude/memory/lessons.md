# 教訓ログ（Lessons）

ループが学習するための外部メモリ。セッションを跨いで引き継がれる唯一の資産。

**書き込みは `/loop-retro` 経由。** 手書きで雑に追記しない。
書き方と運用ルールは `@.claude/memory/README.md` を参照。

---

## 使い方（このテンプレを導入したプロジェクトでの初手）

1. 最初の Issue が完了したら `/loop-retro` を実行し、この下に教訓を積む
2. 立案のメイド（Planner）は分解前に必ずこのファイル全体を読む
3. 同じ事象が再発したら、新規追加ではなく既存項目に日付を追記する

### 2026-09-15 / #11 上書きできる値で紐付けた検証は、その値ごとコピーされて無意味になる
- **事象**: `.vault`（端末ごとの Vault パス）を他プロジェクトへ持ち込ませないため、プロジェクト名で紐付けた。`.project`（名前の上書きファイル）も同じ経路でコピーされると照合が素通りし、別プロジェクトの記録が元の持ち主の Vault に書き込まれた
- **原因**: 紐付けに使った値が、守ろうとしている攻撃経路（作業ツリーごとのコピー）で一緒に運ばれるものだった。`.project` も `LOOP_PROJECT_NAME` も表示名を上書きするための仕組みで、`.vault` と同じディレクトリにある
- **対処**: `loop-journal.sh` に `project_identity()`（共通 `.git` の実パス・上書き不可）を新設し、紐付けはこれだけで行う。表示名（`project_name()`）は Vault のファイル名専用に分離した
- **次回ルール**: 何かを「本物かどうか」で弾く検証を書くときは、**照合に使う値が偽装経路で一緒に運ばれないか**を先に確認する。運ばれるなら別の値を探す

### 2026-09-15 / #11 検証を1つの関数の一部にだけ掛けると、そこが穴になる
- **事象**: ポインタの2行目にはサニタイズを掛けたが、19行上の1行目は生のまま出力していた。`journal/*.md` にはシンボリックリンク検査を掛けたが、同じディレクトリの `.vault` / `.project` / `.active` には掛けていなかった
- **原因**: 「この値は外部由来だ」と判断した時点で境界を引いたつもりになり、**同じ境界を越える他の値を数えなかった**
- **対処**: `safe_display()` と `read_pointer()` に括り出し、境界を越える全ての読み書きを通した
- **次回ルール**: 入力に検証を足すときは、**その入力の行き先（生成物・記録・報告・パス・削除対象）を列挙してから**書く。1つでも数え漏らせばそこが穴になる

### 2026-09-15 / #11 `--git-common-dir` は「このディレクトリがそのリポジトリの一部か」には答えない
- **事象**: worktree の `.git` はディレクトリではなく gitdir ポインタ**ファイル**で、`cp -r` に付いてくる。コピー先が元リポジトリの同一性を名乗り、照合を素通りした
- **原因**: 「どのリポジトリか」を聞く API で「このディレクトリはそのリポジトリの一部か」を判定しようとした。聞くべき質問が違った
- **対処**: git が `<common>/worktrees/<name>/gitdir` に記録している「あるべき場所」と実際の位置を突き合わせる（`project_identity()`）。macOS では `/private` 経由のリンクがあるため `pwd -P` で実パスに解決してから比較する
- **次回ルール**: git の抽象に判定を丸投げしない。**その API が実際に答えている質問**を確かめる

### 2026-09-09 / #10 `grep` は行単位で判定するため、複数行入力が検証をすり抜ける
- **事象**: `printf '%s' "$x" | grep -Eq '^[A-Za-z0-9._-]*$'` 形式の検証が、`ok\n../evil` のような複数行入力を通した。1行目がマッチすれば合格になる。traversal を防ぐ `valid_slug` 本体を含め、同じ書き方を3箇所にコピーしていた
- **原因**: 正規表現の `^...$` が「文字列全体」に掛かると思い込み、`grep` の入力単位を確認しなかった
- **対処**: 検証を全て `case`（文字列全体を1パターンと突き合わせる）へ置換。`tests/scripts/shell-lint.test.sh` で機械検出する
- **次回ルール**: シェルの入力検証に `grep` を使わない。`case "$v" in *[!許可文字]*) 拒否 ;; esac` で書く

### 2026-09-09 / #10 破壊的操作の手前の判定をコマンド置換の中でやると、親は止まらない
- **事象**: `vf="$(require_vault_file)"` の中で `die`（`exit 1`）を呼んでいた。Vault 未接続でもサブシェルしか死なず、親は続行して `rm -f` に到達し、**内部ジャーナルを削除した**（記録の消失）
- **原因**: 「検証関数の中で die すれば安全」という前提が、`$( )` では成立しないことを確認していなかった
- **対処**: 判定を親シェルへ出す（`vf="$(vault_file)" || die ...`）。削除は Vault への着地を実測（追記行数の差分）で確認した後にのみ行う
- **次回ルール**: `rm` / `mv` / リダイレクトの手前の判定は**必ず親シェルで**書く。`$( )` の中で `exit` しても親は死なない
- **再発**: 2026-09-09 #10（`write_state` が正しく 1 を返すのに呼び出し側4箇所が戻り値を捨てており、retry が永久に加算されずハードストップが静かに死んだ。**形は違うが「止めたつもりが止まっていない」という同じ失敗**）

### 2026-09-09 / #10 壊れた状態ファイルは「続行してよい」と解釈されうる
- **事象**: `LOOP_MAX_RETRY=abc` のようなタイプミスで `jq --argjson` が落ち、0バイトの `loop-state.json` が残った。以後 `check` は全比較が失敗して **exit 0（続行可）** を返し、`loop-guard.sh` も素通しした。ハードストップが完全に無効化された
- **原因**: 状態が読めないケースを「判定不能」ではなく「問題なし」として扱っていた。比較が失敗したときに何が起きるかを確認していなかった
- **対処**: `loop-state.sh` を fail closed に。状態が空・不正なら停止する。上限の環境変数を境界で検証し、不正なら警告して既定へ倒す。`write_state` は生成した JSON を検証してから置き換える
- **次回ルール**: ハードストップに関わる判定は**読めなければ止まる側**に倒す。「判定できなかった」を「合格」と同じ扱いにしない

### 2026-09-09 / #6 テストランナーやバージョン指定を推測でフラグ化すると、導入先で必ず落ちる
- **事象**: 生成する CI に `npm test -- --run` を無条件で入れ、Jest プロジェクトの CI が 100% 赤くなった（`--run` は Vitest 専用）。`engines.node: ">=18 <21"` から数字だけ抜いて `1821` という存在しないバージョンを生成した
- **原因**: 「たぶんこう書けば動く」で出力を決めた。依存関係や指定の形式という**確認できる事実**を見なかった
- **対処**: `devDependencies` に `vitest` があるときだけ `--run` を付ける。`engines.node` は単項の単純指定のみ採用し、範囲・OR は警告して既定へ倒す。yarn / bun の `audit` はコマンドが版で割れるため生成せず案内に留める
- **次回ルール**: 生成物に書く値は**事実から決まるものだけ**にする。一意に決められない入力は推測せず、既定へ倒して警告する

### 2026-09-09 / #5 全部 PASS は、テストが何も検査していなくても起きる
- **事象**: `assert_file_not_contains "$CI_FILE" -- "--run"` が3引数を渡していたが関数は `$2` しか見ず、実際は `"--"` を検査していた。別のテストは空白除去で文字列が一致しなくなるため、防御が無くても通った
- **原因**: アサーションを書いた時点で「検査できたつもり」になり、**壊して落ちることを確認しなかった**
- **対処**: 隔離コピーに変異を注入して、意図した件数が FAIL することを毎回確認する運用にした
- **次回ルール**: 回帰テストを足したら**必ず変異注入で落ちることを確認する**。落ちないテストは通っていることの証明にならない

### 2026-09-09 / #5 多バイト文字に隣接する変数展開は bash が変数名に飲み込む
- **事象**: `"...: $vf（epic: $epic）"` のような日本語メッセージで `unbound variable` が発生し、スクリプトが途中で死んだ
- **原因**: bash が `$vf（` の全角括弧までを変数名の一部として解釈する。`set -u` 下では即死する
- **対処**: 多バイト文字に隣接する展開を全て `${var}` で囲む。`tests/scripts/shell-lint.test.sh` で機械検出する（`grep -P` は macOS の BSD grep が非対応なので perl を使う）
- **次回ルール**: 日本語メッセージ内の変数展開は**常に `${var}`** で書く。コメント内も同じ
- **再発**: 2026-09-08 #3 / 2026-09-09 #5 / 2026-09-15 #11（計4回。3回目以降は shell-lint が検出した。**機械化していなければ出荷していた**）

### 2026-09-15 / 運用 自己レビューは機能しない。独立レビューを飛ばすな
- **事象**: このセッションで独立レビュー（`sub-agent-evaluator` / `sub-agent-spec-reviewer` / `sub-agent-security-reviewer`）が重要度「高」8件・「中」十数件を検出した。**同じコードに対する自己レビューでは1件も出なかった**
- **原因**: 設計した本人は、自分が想定した使い方しか試さない。異常系・敵性入力の発想が出てこない
- **対処**: G3 / G4 / G5 を PR ごとに通す。差し戻しは実装（Coder 相当）へ戻し、指摘された箇所だけでなく**同じ障害クラスの別経路**も探す
- **次回ルール**: ゲートを「通ったことにする」判断を自分でしない。**5巡連続で「直した箇所の隣」から新しい高指摘が出た**という事実を前提に動く

### 2026-09-15 / 運用 テストの実行結果を見ずにコミットした
- **事象**: `shell-lint` が多バイト隣接の変数展開を検出していたのに、同じコマンドブロックでテストとコミットを連結していたため結果を確認せず push した
- **原因**: `bash tests/run.sh | grep ...` の後ろに `&&` ではなく `;` でコミットを続けた。仕組みは正しく検出していたが、人間側が握り潰した
- **対処**: `if bash tests/run.sh; then ... else 失敗として止める` の形で検証する
- **次回ルール**: 検証コマンドとコミットを同じブロックに書くときは、**必ず終了コードで分岐させる**。出力を目で追う前提にしない

### 2026-09-15 / 運用 squash マージで base ブランチを消すと、それを base にした PR が閉じられる
- **事象**: スタックした PR #8 の base（`feat/5-template-ci`）を `gh pr merge --delete-branch` で消した瞬間、#8 が main に付け替わらず **CLOSED** になった。base が無いため reopen もできない
- **原因**: GitHub は base ブランチが消えた PR を自動で付け替えない
- **対処**: base ブランチを一時的に push し直して reopen → base を main へ変更 → 一時ブランチを削除。その後 squash 由来の衝突を、`main` のツリーが元の先端と一致することを確認した上で解消した
- **次回ルール**: スタック PR は**下から順にマージし、下をマージしたら上の base を先に main へ付け替えてから**、下のブランチを消す
