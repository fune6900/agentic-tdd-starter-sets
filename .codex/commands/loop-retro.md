# loop retro（Reflection）

失敗を言語化して外部メモリに記録する。ループが学習するための唯一の手段。

## いつ実行するか（いずれも必須）

- インナーループ完了直後（差し戻しが1回でも発生した場合）
- ハードストップ発動直後（解決できなかった事実こそ価値がある）
- 同じ指摘を2回以上受けたとき

差し戻しゼロで終わった場合のみスキップしてよい。その旨を報告する。

## 手順

1. 事実を集める:
   ```bash
   bash .claude/scripts/loop-state.sh show
   git log --oneline main..HEAD
   git diff main...HEAD --stat
   ```
2. 「次回ルール」が書ける事象だけを教訓として抽出する。書けない事象は記録しない。
   - 記録する: このコードベース固有の落とし穴 / ライブラリの想定外挙動 / 規約解釈のぶれ /
     受け入れ条件の設計漏れ / 解決できなかった問題と無駄だったアプローチ
   - 記録しない: 一般論 / 単純なタイプミス / 一度きりの環境問題
3. `grep -n "次回ルール" .claude/memory/lessons.md` で重複を確認する。
   既存の教訓と同じなら新規追加せず、`- **再発**: <日付> #<番号>` を追記する。
4. `.claude/memory/lessons.md` の「## 教訓」直下に、新しいものを上に追記する:
   ```md
   ### YYYY-MM-DD / #<Issue番号> <一行タイトル>
   - **事象**: <観測できた事実のみ>
   - **原因**: <確認できた原因。不明なら「未確定」と明記>
   - **対処**: <どう直したか。ファイル名まで>
   - **次回ルール**: <次のセッションが読んで行動を変えられる一行>
   ```
   ハードストップの場合は `- **未解決**:` と `- **試して無駄だったこと**:` を併記する。
5. 同じ教訓が3回再発している場合は、`.claude/rules/` への恒久ルール化を提案する。

## Codex 注意点

- 取り繕わない。学習が効かなかったなら、効かなかったと書く。
- 原因が特定できていない場合は「未確定」と明記する。断定した誤情報は次を誤誘導する。
- `lessons.md` はコミットする。ローカルに置き去りにしない。
- 30項目を超えたら整理と陳腐化項目の削除を提案する。
